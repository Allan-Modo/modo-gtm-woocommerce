Modo GTM WooCommerce — Guide de refactorisation MVC

Ce document explique les changements apportés pour migrer le plugin vers une structure MVC, l’organisation du code et comment l’étendre.

Objectifs

  • Isolation par responsabilité (évènements, settings, assets).
  • Suppression des doublons de hooks.
  • Factorisation de la construction des données eCommerce.
  • Extensibilité améliorée.

Architecture

  • Controllers: app/Controllers/Events/*Controller.php, app/Controllers/Admin/SettingsController.php, app/Controllers/Frontend/AssetsController.php
  • Models: app/Models/EventDataBuilder.php
  • Views: app/Views/scripts/push-event.php, app/Views/admin/settings-page.php
  • Core: app/Core/Autoloader.php, app/Plugin.php

Circuit de chargement

// modo-gtm-woocommerce.php
require_once MODOGTMWC_PATH . 'app/Core/Autoloader.php';
\ModoGtmWc\Core\Autoloader::register();
require_once MODOGTMWC_PATH . 'app/Plugin.php';
\ModoGtmWc\Plugin::init();
  
// app/Plugin.php
add_action('plugins_loaded', [Plugin::class, 'register_hooks']);
// Enregistre Events, Settings (admin), Assets (front)

Détails par évènement

View Item

  • Hook: woocommerce_after_single_product
  • Contrôleur: app/Controllers/Events/ViewItemController.php
  • Variantes: depuis $_GET['attribute_*'], jointure ,
$event_data['ecommerce'] = [
  'currency' => get_woocommerce_currency(),
  'value'    => (float) $product->get_price(),
  'items'    => [$builder->buildItem($product, 1, ['variant_join' => ','])],
];

Add To Cart

  • Hooks: woocommerce_add_to_cart, woocommerce_loop_add_to_cart_link
  • Contrôleur: app/Controllers/Events/AddToCartController.php
  • AJAX via assets/front/js/front-script.js
$item = $builder->buildItem($product, (int) $quantity, [
  'variation_values' => is_array($variation) ? array_values($variation) : [],
  'variant_join'     => ',',
]);

Remove From Cart

  • Filtre: woocommerce_cart_item_remove_link
  • Valeur: line_total, coupon du panier si présent

Purchase

  • Hook: woocommerce_thankyou
  • Items: price = line_total / quantity, index incrémental

View Item List

  • Hooks: the_post (collecte), wp_footer (rendu)
  • Pas de variantes. Contexte liste (Shop/Cat/Search).

Construction des items

Fichier: app/Models/EventDataBuilder.php

buildItem(\WC_Product $product, int $quantity = 1, array $opts = [])
// opts: suppress_variants, variation_values, variant_join
  • Marque sur parent si variation.
  • Catégories « smart » (profondeur max) ou niveau 1.
  • Remises: variation > variable > simple.
  • Variantes: hook > variation > variable (GET/defaults).

Settings/Admin

  • Contrôleur: app/Controllers/Admin/SettingsController.php
  • Vue: app/Views/admin/settings-page.php
  • Mêmes option_name et groupes que l’original.

Frontend assets

  • Contrôleur: app/Controllers/Frontend/AssetsController.php
  • Gère assets/front/js/front-script.js.

Débogage

  • Vérifier le chemin vue: app/Views/scripts/push-event.php.
  • Consulter wp-content/debug.log.
  • Inspecter window.dataLayer dans la console.

Bootstrap et Autoloader

modo-gtm-woocommerce.php

require_once MODOGTMWC_PATH . 'app/Core/Autoloader.php';
\ModoGtmWc\Core\Autoloader::register();
require_once MODOGTMWC_PATH . 'app/Plugin.php';
\ModoGtmWc\Plugin::init();

Charge l'autoloader et le coeur; les anciens hooks/events/settings sont migrés dans app/Plugin.php.

app/Core/Autoloader.php

$prefix = 'ModoGtmWc\\';
$base_dir = dirname(__DIR__, 1) . DIRECTORY_SEPARATOR; // app/
$relative_class = substr($class, $len);
$file = $base_dir . str_replace('\\', DIRECTORY_SEPARATOR, $relative_class) . '.php';

Transforme un nom de classe en chemin sous app/, puis require si présent.

app/Plugin.php

add_action('plugins_loaded', [Plugin::class, 'register_hooks']);
if (class_exists('WooCommerce')) { /* enregistre events */ }
if (is_admin()) { (new SettingsController())->register(); }
(new AssetsController())->register();

Contrôleurs d’évènements

ViewItemController

Hook: woocommerce_after_single_product. Construit ecommerce avec value = prix, variantes jointes par « , ».

AddToCartController

  • woocommerce_add_to_cart: non‑AJAX, injection en footer.
  • woocommerce_loop_add_to_cart_link: ajoute data-event_data pour le JS.
  • value = unit_price * quantity, variantes depuis le hook.

RemoveFromCartController

  • Filtre lien remove: injecte data-event_data.
  • item.price et ecommerce.value définis à line_total.
  • Coupon du panier si présent.

PurchaseController

  • Hook thankyou: transaction_id, currency, value.
  • Items: price = line_total / quantity, index, catégories corrigées.

ViewItemListController

  • Collecte via the_post, rendu unique en footer.
  • Pas de variantes, définit index, remplit item_list_id/name.

Admin et Frontend

SettingsController

Enregistre la page d’options et les champs (Settings API), conserve les option_name existants.

AssetsController

Enqueue du script front assets/front/js/front-script.js pour gérer AJAX et remove.

Dépannage (render_view)

Si rien n’est injecté, vérifier le chemin du template en footer. Tous les contrôleurs doivent pointer vers app/Views/scripts/push-event.php.
